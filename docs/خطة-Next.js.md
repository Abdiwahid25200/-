## ⏭️ المهمة التالية — المرحلة ٣

1. مشروع Firebase `ermaan-new` · مفتاح السيرفر في **Vercel Environment Variables** (لا يُرفع على GitHub)
2. **مستند مستقل لكل طلب** بدل المصفوفة الواحدة — هذا أساس الأمان

6. تفعيل: حفظ الطلبات · رفع الإيصال · تسجيل دخول الزبون · التحقق من آيدي ببجي

- **رقم واتساب والإيميل** — ستضيفهما من لوحة الإدارة (المرحلة ٤). الحقول جاهزة في `lib/content.ts` وتظهر تلقائياً عند تعبئتها.

## 🔴 المشاكل الأربع اللي تدفعنا للانتقال

### 1) الكود مكرر — والاختلاف الصامت **صار فعلاً**

`admin.html` يحتوي نسخة كاملة من موقع الزبون، مخفية بـ `body.admin-mode` (مستخدمة 17 مرة بالـCSS).

**الدليل على الاختلاف:** تدفّق الشراء الجديد موجود بـ`index.html` ومفقود تماماً من `admin.html`:

| الدالة | `index.html` | `admin.html` |
|---|:---:|:---:|
| `mbSelect` · `mbPickPay` · `mbRender` | ✅ | ❌ |
| `mbSetRcpt` · `mbConfirm` | ✅ | ❌ |
| `MB` (كائن الحالة) | ✅ | ❌ |
| `applyClosedState` | ✅ | ❌ |

**بـ Next.js:** المكوّن يُكتب **مرة واحدة** ويُستخدم بالمكانين. المشكلة تختفي هيكلياً — مو بالانضباط، بل بالتصميم.

---

### 2) 🚨 ثغرة أمنية — بيانات الزبائن مكشوفة

ملف `firestore.rules` الحالي فيه:

```
allow read: if true;
```

**النتيجة:** أي شخص بالعالم يقدر يقرأ — بدون كلمة سر ولا حساب:

| البيانات | الحساسية |
|---|:---:|
| أسماء الزبائن وأرقام واتساب وعناوينهم | 🔴 |
| صور إيصالات الدفع | 🔴 |
| **إيميلات وكلمات سر حسابات eFootball** (`gEmail`, `gPass`) — بدون تشفير | 🔴🔴 |
| المحادثات الخاصة · حسابات الزبائن · رسائل الدعم | 🔴 |

**وأخطر:** كل الطلبات محفوظة بمستند واحد، وموقع الزبون يحمّله كامل عشان يعرض "طلباتي".
→ **كل زبون يفتح صفحة طلباته، ينزّل على جهازه طلبات كل الزبائن.** التسريب يصير الآن، يومياً.

**ومشكلة الكتابة:** القاعدة تسمح لأي `auth != null`، و`firebase-adapter.js` يسجّل كل زائر دخولاً مجهولاً تلقائياً (`signInAnonymously`).
→ **أي زائر يقدر يستبدل قائمة الطلبات كاملة = مسح كل طلبات المتجر.**

**السبب الجذري:** قواعد Firestore تحمي **المستندات**، لا العناصر داخلها. وكل الطلبات بمستند واحد.

**الحل:** مستند مستقل لكل طلب + قراءة عبر السيرفر. ← المرحلة 3

---

### 3) ⏳ قنبلة موقوتة: الصور مخزّنة داخل قاعدة البيانات

فحصت `admin.html` — رفع الصور يستخدم `toDataURL` ويحفظ الصورة **نصاً داخل Firestore**، ولا يوجد أي استخدام لـ Firebase Storage (صفر إشارات).

| الحقيقة | الرقم |
|---|---|
| الحد الأقصى لمستند Firestore | **1 ميجابايت** |
| كل منتجاتك + إعداداتك | **بمستند واحد** (`marjan-somalia-db`) |
| صورة مضغوطة بصيغة base64 | ~30–80 كيلوبايت |

**يعني: بعد ~20–30 منتج بصور، تضربين السقف.**

**وش يصير وقتها؟** الحفظ يفشل. ممكن بدون رسالة خطأ واضحة — تضيفين منتج وما ينحفظ، وما تعرفين ليش.

**الحل:** الصور تنرفع لتخزين حقيقي (Vercel Blob أو Firebase Storage)، وقاعدة البيانات تحفظ **الرابط فقط** (~60 حرف بدل 60 ألف). ← المرحلة 3

---

### 4) 🐌 الأداء

الزائر ينزّل ملف 328 KB كامل قبل ما يشوف أي شي — حتى لو بس يبي يتصفح صفحة وحدة. وجوجل ما يقدر يفهرس منتجاتك (كلها تُبنى بالجافاسكربت بعد التحميل).

**بـ Next.js:** كل صفحة تحمّل نفسها فقط، والصفحات تُبنى على السيرفر → أسرع بكثير + منتجاتك تظهر بجوجل.

### ⭐ ملاحظتان مهمتان

**1) مجلد `components/` هو حل مشكلة التكرار.**
بطاقة المنتج تُكتب مرة واحدة → تُستخدم بموقع الزبون وبلوحة الإدارة. تعديل واحد = يظهر بالمكانين. **مستحيل يصير اختلاف صامت.**

**2) ملف `lib/store.ts` هو "طبقة عازلة".**
كل الكود يتعامل مع هذا الملف فقط، وهو اللي يتكلم مع Firestore. فلما نغيّر طريقة تخزين الطلبات بالمرحلة 3، **نعدّل هذا الملف بس** — باقي الموقع ما يحس.
