# قواعد العمل الموفّرة — Ramaan Store

الهدف: **إنجاز كل الشغل في جلسة واحدة**، بدون أي تنازل عن سلامة المشروع.

---

## ١. ابدأ من ملف الحالة، لا من الخطة

```
✅ اقرأ  docs/الحالة.md          ← ٦٠ سطراً  · ≈ ٦٠٠ توكن
❌ لا تقرأ docs/خطة-Next.js.md   ← ٧٠٠ سطر  · ≈ ٧٠٠٠ توكن
```

`docs/الحالة.md` فيه: المنجز · الخطوة التالية · المعلّق · خريطة الملفات · القرارات المحسومة.
**لا تفتح الخطة الكاملة** إلا لو احتجت تفصيلاً غير موجود في ملف الحالة.

- ❌ لا تعيد استكشاف بنية المشروع — الخريطة في ملف الحالة
- ❌ لا تقرأ أي ملف وثائق مرتين في نفس الجلسة

**🔄 في نهاية كل خطوة عمل: حدّث `docs/الحالة.md`** (سطرين أو ثلاثة).
هذا هو ما يجعل الجلسة تنجو من الضغط (`/compact`) دون خسارة أرض.

---

## ٢. 🚨 ملفات الموقع القديم — أكبر مصيدة استهلاك

```
docs/الموقع-القديم/index.html   →  81,000 توكن
docs/الموقع-القديم/admin.html   →  94,000 توكن
```

**قراءة الاثنين كاملين = ١٧٥ ألف توكن = جلسة كاملة محروقة.**

### 🔴 ممنوع منعاً باتاً

```
Read("docs/الموقع-القديم/index.html")     ❌
Read("docs/الموقع-القديم/admin.html")     ❌
```

### ✅ الطريقة الصحيحة — خطوتان

```bash
# ١) حدّد الموقع بالضبط
Grep -n "اسم_الدالة" docs/الموقع-القديم/index.html

# ٢) استخرج الكتلة المطلوبة فقط (٤٠ سطراً كحد أقصى)
sed -n '1960,1990p' docs/الموقع-القديم/index.html
```

**للإحصاء والمقارنة، استخدم الطرفية لا القراءة:**

```bash
grep -c "pattern" file            # عدّ
grep -o "pattern" file | sort -u  # قيم فريدة
comm -13 a.txt b.txt              # فروقات
```

## ٣. البناء والاختبار

| ✅ افعل | ❌ لا تفعل |
|---|---|
| ابنِ **مرة واحدة** بعد مجموعة تعديلات مترابطة | بناء بعد كل ملف |
| `npm run build 2>&1 \| tail -20` | طباعة المخرجات كاملة |
| `npm install` عند تغيّر `package.json` فقط | إعادة التثبيت بلا سبب |
| ثق بأن `Edit` نجح — يعطي خطأ لو فشل | إعادة قراءة ملف عدّلته للتو |

**قبل تشغيل خادم:** أغلق القديم أولاً وإلا اختبرت نسخة قديمة بالغلط.

```bash
for pid in $(ss -lptn 'sport = :3000' | grep -oP 'pid=\K[0-9]+' | sort -u); do kill -9 $pid; done
```

> ⚠️ لا تستخدم `pkill -f "next start"` — النمط يطابق أمر الطرفية نفسه ويقتل الجلسة.

## ٤. لقطات الشاشة — مكلفة

**كل صورة ≈ ١٥٠٠+ توكن.**

| ✅ | ❌ |
|---|---|
| لقطتان كحد أقصى لكل خطوة | ٤ لقطات "للتوثيق" |
| `viewport` (حجم الشاشة) | `fullPage` — يضاعف الحجم |
| فقط لو النتيجة **بصرية** | بعد تعديل منطقي لا يُرى |
| أرسلها لها بـ `SendUserFile` | اقرأها بنفسك ثم أرسلها (تُحتسب مرتين) |

اقرأ اللقطة بنفسك **فقط** عند الشك في وجود خلل بصري.

---

## ٥. الردود — أقصر = أوفر

صاحبة المشروع **غير مبرمجة وتقرأ من الآيباد**. المطلوب:

- ✅ العربية · نقاط مرقّمة · **جداول بدل الفقرات**
- ✅ ملخص واحد في نهاية الخطوة
- ❌ لا تكرر ما قيل في نفس الجلسة
- ❌ لا تسرد خطوات لن تنفّذها
- ❌ لا تشرح الكود سطراً سطراً — اشرح **النتيجة**

**قاعدة:** لو الرد أطول من شاشتين على الجوال، اختصره.

## ٦. ممنوعات توفيرية

| ❌ | السبب |
|---|---|
| استدعاء `Agent` / وكلاء فرعيين | كل وكيل يبدأ من الصفر ويعيد اشتقاق السياق — الأغلى |
| بحث واسع بلا هدف | حدّد الملف والنمط أولاً |
| إعادة سرد سياق المشروع | موجود في `docs/` |
| قراءة `package-lock.json` | لا فائدة منه |

**استدعاءات الأدوات المستقلة: نفّذها دفعة واحدة** في رسالة واحدة، لا واحدة تلو الأخرى.

---

## ٧. 🕐 إطالة عمر الجلسة — الأهم

هي تريد **جلسة واحدة تكفي كل الشغل**. أكبر ثلاثة أعداء:

| العدو | العلاج |
|---|---|
| قراءة ملفات كبيرة | ملف الحالة بدل الخطة · `sed` بدل `Read` |
| اللقطات | لقطة واحدة عند الحاجة البصرية فقط |
| تكرار العمل بعد الضغط | **حدّث `docs/الحالة.md` باستمرار** |

### قواعد الجلسة الطويلة

1. **اجمع طلباتها ثم نفّذ دفعة واحدة** — بناء واحد، رفع واحد، فحص واحد
2. **لا تعيد قراءة ملف قرأته في هذه الجلسة** — محتواه ما زال معك
3. **لا تعيد قراءة ملف عدّلته للتو** — `Edit` يفشل بصوت عالٍ لو لم ينجح
4. **استخدم الطرفية للتحقق بدل القراءة:**
   ```bash
   git diff --stat            # ما الذي تغيّر
   grep -c "pattern" file     # عدّ بدل فتح الملف
   npm run build 2>&1 | tail -20
   ```
5. **الأوامر المستقلة في رسالة واحدة** — لا واحدة تلو الأخرى
6. **قبل إنهاء أي كتلة عمل:** كوميت + تحديث ملف الحالة

### متى تقترح `/compact`

اقترحها عليها بجملة واحدة **بعد إنهاء كتلة عمل ورفعها** — لا في منتصف مهمة.
الوقت المثالي: بعد الكوميت مباشرة، لأن ملف الحالة يكون محدّثاً والأرض محفوظة.

---

## ٨. 🔄 بروتوكول ما بعد الضغط (`/compact`)

بعد أي ضغط للسياق، **بهذا الترتيب وبلا زيادة**:

```
١) اقرأ  docs/الحالة.md
٢) شغّل  git log --oneline -3 && git status --short
٣) أكمل الخطوة التالية المكتوبة في ملف الحالة
```

- ❌ لا تعيد استكشاف المشروع
- ❌ لا تلخّص ما مضى لها — أكمل مباشرة
- ❌ لا تسألها "أين كنّا؟" — الجواب في ملف الحالة

---

## ٩. 🛡️ ما لا يُوفَّر فيه أبداً

**التوفير في الوقت، لا في السلامة.** هذه القواعد لا تُختصر مهما كان:

1. **ابنِ واختبر محلياً قبل أي رفع** — لأنها لا تستطيع الاختبار من الآيباد
2. **اشرح قبل التنفيذ وخذ الموافقة** — خطوة واحدة كل مرة
3. **لا تحذف ولا تستبدل ملفاً قبل السؤال**
4. **نسخة احتياطية قبل أي تعديل كبير**
5. 🔒 **لا ترفع مفاتيح سرّية إطلاقاً** — تُحفظ في Vercel Environment Variables
6. **عند الخطأ: قف واشرح** — لا تكمل على أمل أن ينحل

> اختصار خطوة تحقّق يوفّر ألف توكن اليوم، ويكلّف جلسة كاملة غداً.
